## Suggested evidence files to submit

For requirements 1–8, use the linked source and test files in the table, plus the sample output files where listed. For the remaining assessment-only claims, submit new evidence rather than treating source code as proof:

- **1:** Record a real script/TTS job and real MP3, WAV, and M4A uploads; include resulting job IDs, status/output links, and a 10-minute boundary validation.
- **2:** Submit a generated job's `timeline.json`, matching `captions.srt`, source audio/transcript, and a dated screen/video recording where the reviewer checks each cut against spoken sentence/phrase boundaries.
- **3:** Submit the per-job `timeline.json` and `manifest.json` plus a human-checked item/source/license/attribution/watermark register for every selected visual.
- **4:** Submit 16:9, 9:16, and 1:1 MP4s, their manifests, and automated FFprobe/black/freeze/sync-check output.
- **5:** Submit the video and timeline together with a dated, per-scene human 1–5 relevance sheet. The existing machine score is not that sheet.
- **6:** Submit new safety controls, hard-case tests, and a dated review of named people, brands/logos, and sensitive news.
- **7:** Submit the fallback test log and output, plus a live recording showing a provider disabled/failing mid-job.
- **8:** Submit a corrected OpenAPI document, API contract-test output, and a live demo recording with timestamps for submission, progress, result, and download.

The two sample script output groups linked above contain actual repository files. They are not live-demo recordings. Their timeline `generated_at` fields are file-generation timestamps, not verification/demo timestamps.
